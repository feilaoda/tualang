# `Ref<T>` / `&T` 规范

Status: Frozen

本文件定义 CAI 的引用/借用类型：`Ref<T>`，以及语法糖 `&T`。

目标：
- 不暴露裸指针地址；
- 在无 GC 前提下，提供可预测、可静态检查的借用规则；
- 让“读/写权限”在类型与绑定规则中可表达。

---

## 1. 类型与语法
- `Ref<T>` 是命名泛型类型。
- `&T` 是类型语法糖，等价于 `Ref<T>`。

> `cai/parser.g4` 同时允许 `&T` 与 `Ref<T>` 作为类型写法；语义一致。

---

## 2. 只读 vs 可写
CAI 不在类型名上区分 `Ref<const T>` 之类的变体；只读/可写由“绑定模式/参数模式”决定：

### 2.1 绑定产生的权限
对一个可借用值 `x: T`：
- `const r = &x`：产生 **共享只读借用**（read-only）。
- `let r = &x`：产生 **独占可写借用**（read-write，exclusive）。

### 2.2 参数产生的权限
当函数参数类型为 `Ref<T>`（或 `&T`）时：
- `fn f(const p: Ref<T>)`：`p` 为共享只读。
- `fn f(mut p: Ref<T>)`：`p` 为独占可写。

> 语法上 `paramMode` 适用于所有参数；对于 `Ref<T>`，它进一步决定借用权限。

### 2.3 由表达式/API 产生的权限
`Ref<T>` 也可以由表达式或标准库 API 产生（例如 `map.getRef/getMut`、`slice.getRef/getMut`）。

规则：
- 产生 `Ref<T>` 的操作必须在其所属规范中明确该引用是“共享只读”还是“独占可写”。
- 编译器必须按该声明权限进行借用冲突检查；不允许把共享引用当作独占引用使用（或反向“升级”）。

---

## 3. 借用冲突规则（必须冻结的核心）
在同一作用域内，对于同一个 owner 值 `x`：
- 允许任意数量的共享只读借用同时存在；
- 独占可写借用与任何其他借用冲突（存在独占时，不允许再创建共享/独占；存在共享时，不允许创建独占）。

在借用存活期间：
- 禁止移动 owner（若 `T` 为 move-only 类型）；
- 禁止通过 owner 进行可能使引用失效的写（例如容器扩容导致地址变化；具体由各容器规范定义）。

> 借用生命周期的精确定义（NLL/语句级/表达式级）可单独在 `cai/docs/spec/ownership.md` 冻结；本文件冻结的是“冲突与失效”规则。

---

## 4. 可比较性与可空性
- `Ref<T>` 可以为 `null`（若类型系统不区分 nullable）。
- 允许 `==/!= null`。
- 禁止有序比较（`< <= > >=`）。
- `if r {}` 不允许；必须显式写 `r != null`。

---

## 5. 与 `Ptr<T>` 的区别
- `Ref<T>`：语言级借用，受借用检查约束，面向安全默认。
- `Ptr<T>`：受限指针，主要用于 FFI/底层互操作；禁止算术与整数互转，内存访问走受控 API（见 `cai/docs/spec/ptr.md`）。
