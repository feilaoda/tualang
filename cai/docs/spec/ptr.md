# `Ptr<T>` 规范

Status: Frozen

CAI 不提供裸指针类型（例如 `ptr`/`void*`）作为语言内置类型；指针仅以受限形式出现：`Ptr<T>`。

`Ptr<T>` 是一个命名泛型类型（按语法解析为 `namedType`），其语义由本文件冻结。

---

## 1. 值域与布局
- `Ptr<T>` 可以为 `null`。
- `Ptr<T>` 的运行时表示为“机器字宽地址”（`usize` 宽度），但该地址不得被 CAI 程序以整数方式直接观察或运算（见 3/4）。

---

## 2. 比较与布尔上下文
- 允许：
  - `p == null` / `p != null`
  - `p1 == p2` / `p1 != p2`（要求 `p1`/`p2` 类型相同：`Ptr<T>`）
- 禁止：
  - `p < q` / `p <= q` / `p > q` / `p >= q`（编译错误）
  - 对 `Ptr<T>` 做 truthiness（例如 `if p {}`）为编译错误；必须显式写 `p != null`

---

## 3. 运算与转换（严格禁止默认“指针玩法”）
- 禁止指针算术：`p + n`、`p - n`、`p++`、`p[n]` 等均为编译错误。
- 禁止整数互转：
  - `cast(usize, p)` / `cast(Ptr<T>, x)` 形式的转换一律为编译错误（即使存在同位宽）。
  - 不提供任何“地址取整/整数转地址”的标准库 API。

---

## 4. 解引用与内存访问（只能通过受控 API）
CAI 不提供 `*p`、`p->field`、`p[i]` 这类直接解引用语法。

所有内存读写必须通过 `Ptr<T>` 的受控方法（示意；具体方法名在标准库冻结）：
- `p.read() -> T`
- `p.write(v: T) -> void`
- `dst.copyFrom(src: Ptr<T>, count: usize) -> void`

受控 API 的最低要求：
- 明确“是否可能触发 UB”的前置条件（对齐、可读/可写、生命周期、重叠拷贝等）。
- 明确“是否需要 unsafe”的语义边界（如引入 `unsafe`，需在 `cai/docs/spec/unsafe.md` 冻结）。

---

## 5. FFI 约定（语义层）
- `extern fn` 的指针参数/返回值统一使用 `Ptr<T>`（而不是 `void*`/裸地址）。
- “指针 + 长度”一律使用显式结构（例如 `Slice<T>`/`Bytes`），避免 `strlen` 与 NUL 歧义。
- 资源释放不传播 `free(ptr)` 约定；外部资源建议建模为显式句柄类型并提供 `close()/deinit`。
