# 运行时（Runtime）与调度规范

Status: Frozen

本文件冻结 CAI 运行时的最小行为边界：任务调度模型、I/O 事件驱动、阻塞策略与跨平台一致性要求。

CAI 不要求“可嵌入 VM”；但运行时仍是语言/标准库可依赖的基础设施。

---

## 1. M:N 任务调度模型

CAI 运行时必须提供 M:N 协程调度器：
- M 个轻量级任务（Tasks）在 N 个原生 OS 线程上运行；
- `async fn` 调用返回任务对象；任务在 `await` 时协作式让出执行权（见 `cai/docs/spec/async.md`）。

调度保证（冻结）：
- 调度器是**协作式**：任务只会在显式挂起点（`await`、运行时 I/O 等价挂起点）让出 CPU。
- 运行时不得对普通计算代码做“异步抢占/时间片打断”。

---

## 2. I/O 事件驱动（跨平台一致性）

对 I/O 密集型异步操作，运行时必须基于平台原生机制实现非阻塞等待：
- Linux：Epoll
- Windows：IOCP
- macOS：Kqueue

冻结语义：
- 在 `await` 等待 I/O 完成期间，当前任务必须挂起并允许其他任务继续执行；
- I/O 完成后，任务被唤醒继续执行。

---

## 3. 阻塞与非阻塞策略

### 3.1 异步 API
标准库的异步 API（例如网络/定时器）必须：
- 以 `async fn` 暴露；
- 在等待期间挂起任务而不是阻塞调度线程。

### 3.2 同步阻塞调用的处理
当用户调用同步阻塞 API（例如同步文件读写或进程等待）时：
- 若在非 async 上下文：可以阻塞当前 OS 线程；
- 若在 async 上下文：标准库必须选择以下之一（由 API 规范明确）：
  1) 提供对应的 `async` 版本并要求使用它（同步版本在 async 中为运行时错误或编译诊断），或
  2) 将阻塞操作转移到运行时阻塞线程池（不阻塞调度线程），并以 `await` 的形式等待结果。

---

## 4. 计算密集型任务与 Tensor 算子
冻结要求：
- 运行时不得在计算密集型代码中做随机抢占，保证缓存局部性不被调度器破坏。
- 如需让出执行权，必须通过显式挂起点完成。

标准库必须提供显式让出：
- `std.runtime.yield() -> int`（见 `cai/docs/spec/std_runtime.md`）

---

## 5. 运行时初始化
运行时初始化与模块初始化必须满足：
- 对 `exe`：入口必须先完成模块初始化（见 `cai/docs/spec/import.md`），再进入用户 `main`。
- 对 `staticlib/dylib`：宿主可通过 `cai_init() -> int` 初始化库（见 `cai/docs/spec/aot.md`）。

运行时本身是否在 `cai_init()` 内初始化由实现决定，但必须保证：
- 在调用任何 `async`/I/O API 前，运行时处于可用状态；
- 若运行时未初始化，标准库必须返回非 0 错误码或产生明确诊断（由具体 API 冻结）。
