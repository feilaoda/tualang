# 错误模型规范

Status: Frozen

CAI 的目标是“C-speed + 可组合错误处理”，因此采用 **显式、多返回、错误码** 的错误模型，并提供 guard `? { ... }` 作为语法层的早退出辅助。

---

## 1. 错误码类型
- 错误码类型为 `int`。
- 约定：`0` 表示成功；非 `0` 表示失败。

错误码的具体枚举属于标准库/运行时约定（见 `cai/docs/spec/std_error.md`），但必须保证：
- 在同一程序内稳定；
- 文档化且可测试（错误码到字符串的映射函数建议提供）。

---

## 2. 函数返回约定

### 2.1 失败可能的函数
使用多返回，将错误码放在最后：
- `fn f(...) -> T, int`
- `fn f(...) -> T1, T2, int`

成功时：
- `err == 0` 且前置返回值有效。

失败时：
- `err != 0`
- 前置返回值是否有意义必须冻结：
  - 失败时前置返回值为类型零值/未指定值，调用者不得使用（除非文档另行声明）。

### 2.2 永不失败的函数
- 直接返回 `T` 或 `void`，不带错误码。

---

## 3. Guard `call ? { ... }`
语法见 `cai/docs/spec/expressions.md`。

语义：
- `call` 必须返回至少 2 个值，最后一个为 `int` 错误码；
- 若 `err != 0`，执行 guard block；
- guard block 必须中断控制流（`return/break/continue`），禁止落空；
- 若 `err == 0`，guard 表达式结果为“去掉末尾 err 的剩余返回值”。

---

## 4. 运行时错误（panic/trap）
CAI 需要定义一类“不可恢复错误”（运行时错误），典型来源：
- 越界访问（默认开启边界检查）
- `null` 解引用（对禁止/未定义的操作）
- 除零（整数）
- 显式 `panic()`（若提供）

规则：
- 运行时错误必须输出可定位诊断（文件/行/列 + 简要栈回溯若可用）并终止程序（exit code 非 0）。
- 运行时错误不作为 `int` 错误码返回（避免每处都必须传播）。

---

## 5. 与 `extern fn` 的交互
`extern fn` 必须遵循同样约定：
- 成功返回 `0`；
- 失败返回非 0；
并在文档中声明错误码语义。

---

## 6. 与 `Option<T>` 的边界
- `Option<T>` 用于“业务层可缺失”；
- 错误码用于“操作失败/外部系统失败”。

二者可组合：
- `fn get(k) -> Option<V>` 不使用错误码表达“未命中”；
- I/O 等失败用 `-> T, int`。
