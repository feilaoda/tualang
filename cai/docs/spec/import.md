# 模块与导入（`import`）规范

Status: Frozen

本文件定义 CAI 的模块系统、导入语法与解析规则。

---

## 1. 源文件与模块
- 一个源文件（`.cai`）是一个模块。
- 模块的“模块名”默认由其导入路径决定（见 2）。

---

## 2. 导入语法

### 2.1 默认导入
- `import "path/to/mod.cai"`
- `import "path/to/mod.cai" as Alias`

语义：
- 导入一个模块，并在当前作用域中绑定一个模块名（默认为文件名/最后一段；或用 `as` 指定别名）。

### 2.2 选择性导入（from-import）
- `from "path/to/mod.cai" import A, B, C`
- `from "path/to/mod.cai" import A as X, B`

语义：
- 把被导入模块内的公开符号绑定到当前作用域（别名可选）。
- 若符号不存在或不可见（private），为编译错误。

---

## 3. 路径类型与解析

### 3.1 相对路径
以 `./` 或 `../` 开头的导入为相对路径：
- 基于当前源文件所在目录解析。

### 3.2 绝对/根路径
不允许系统绝对路径导入（编译错误），避免构建不稳定与不可移植。

### 3.3 包路径（非相对）
不以 `./`、`../` 开头的导入视为“包导入”：
- 先在标准库根目录中查找（例如 `std/...`）；
- 再在 package 搜索路径中按序查找。

搜索根目录来源：
- `caic` 参数：`--stdlib-dir <dir>`、`--package-dir <dir>[:<dir>...]`
- 环境变量：`CAI_STDLIB_DIR`、`CAI_PACKAGE_DIR`
 - 包清单：当以包方式构建时，工具链必须从 `cai.toml`/`cai.lock` 计算并注入 package roots（见 `cai/docs/spec/package.md`）。

查找规则：
- 若 import path 不带扩展名，则尝试补全 `.cai`
- 对每个 root，按序尝试：
  1) `<root>/<raw>`
  2) 兜底：`<root>/<name>/<name>.cai`（`name` 为最后一段）

---

## 4. 初始化与副作用
- 导入一个模块会执行其顶层语句（按源代码顺序执行一次）。
- 编译器必须在编译期构建模块依赖的 DAG（有向无环图），并据此做循环检测（见 5）。
- 初始化执行顺序冻结为：**深度优先、从左到右** 的拓扑顺序（确定性）。

初始化算法（规范性描述）：
1) 对入口模块（`main` 所在模块，或产物指定的 entry 模块）调用 `Init(m)`；
2) `Init(m)`：
   - 若 `m` 已初始化过：直接返回；
   - 按 `m` 源代码中 `import`/`from ... import ...` 出现的顺序，从左到右枚举其依赖模块 `d1..dn`，对每个依赖先调用 `Init(di)`；
   - 依赖初始化完成后，执行 `m` 的顶层语句（按源代码顺序）；
   - 标记 `m` 已初始化。

> 同一个模块无论被导入多少次，顶层初始化只执行一次。

---

## 5. 循环导入
循环导入（模块依赖图存在环）默认严格禁止：
- 若存在循环导入，编译器必须报错并展示导入链路。

解耦规则（语言允许且工具链可推荐）：
- 如需打破依赖环，推荐通过 `trait` 抽象接口解耦：让依赖指向抽象层而不是具体实现模块（见 `cai/docs/spec/trait.md` 与 `cai/docs/spec/impl.md`）。

---

## 6. 可见性（public/private）
- `private` 声明的符号仅在同一模块内部可见。
- 其余符号默认可导出（public）。
