# 性能语义与优化边界规范

Status: Frozen

本文件冻结 CAI 为“可预测高性能”提供的语义保证与优化边界。它不绑定具体后端（LLVM/MLIR/自研后端），而是定义：编译器与标准库**可以依赖**哪些语义来做优化，以及哪些行为不得被优化破坏。

---

## 1. 总目标
- 语义优先：任何优化不得改变可观察行为（包括错误码、运行时错误、I/O、副作用顺序）。
- 可证明的性能：通过更强的类型/所有权/借用语义，让编译器能安全地产生更激进的优化结果。

---

## 2. 别名（aliasing）与内存可变性保证

CAI 的主要优化空间来自“可证明的别名关系”，由以下规范共同冻结：
- `Ref<T>` 的共享只读/独占可写借用：`cai/docs/spec/ref.md`
- `Slice<T>` 的共享只读/独占可写权限：`cai/docs/spec/slice.md`
- 借用冲突与逃逸限制：`cai/docs/spec/ownership.md`

编译器可依赖的保证（冻结）：
- 同一 owner 上：
  - 共享只读借用可任意并存；
  - 独占可写借用与任何其他借用冲突。
- 编译器可把“独占可写借用”在中间表示中等价处理为 `noalias`/`restrict` 语义（后端如何实现不冻结）。
- 共享只读借用可被视为“只读视图”，允许做 CSE、load hoist、向量化等优化，但不得跨越任何可能写入同一内存的点。

禁止的优化（冻结）：
- 不得把共享只读借用提升为可写语义；
- 不得把独占可写借用与其他别名视为可并存；
- 不得在仍存活的借用期间移动/重分配 owner（对容器的具体限制由容器规范冻结）。

---

## 3. 错误码模型与控制流

CAI 的错误处理采用 “多返回 + `int` 错误码”：
- 语义总览：`cai/docs/spec/error.md`
- 标准库错误码与分类：`cai/docs/spec/std_error.md`
- guard `? {}`：`cai/docs/spec/expressions.md`

编译器可依赖的保证（冻结）：
- 错误码 `0` 表示成功；非 0 表示失败。
- 对 “失败时前置返回值不得使用” 的函数，编译器可将失败路径视为“冷路径”进行布局优化（如冷分支分离），但不得消除失败分支或改变其副作用（如必须执行的 `defer`）。
- `call ? { ... }` 的 guard block 必须中断控制流，因此编译器可将 guard 视为“成功路径直通，失败路径早退出”的结构化控制流。

---

## 4. async/await 与调度语义（性能可预测）

CAI 的并发语义由语言与运行时共同冻结：
- `async/await`：`cai/docs/spec/async.md`
- 运行时调度：`cai/docs/spec/runtime.md`

编译器/运行时可依赖的保证（冻结）：
- 调度器是协作式：任务只会在显式挂起点（`await` 等）让出执行权；
- 运行时不得对普通计算代码做异步抢占；
- I/O 等待期间挂起任务而不是阻塞调度线程（由标准库 async API 冻结）。

因此：
- 计算密集型代码的缓存局部性不会被“随机抢占”破坏；
- I/O 密集型代码可用大量轻量任务获得高并发而不产生同等数量 OS 线程开销。

---

## 5. ABI/布局稳定与跨库零拷贝

CAI 冻结了可用于跨模块/跨库零拷贝传递的数据形态：
- ABI 与布局：`cai/docs/spec/abi.md`
- `Slice<T>`（视图）：`cai/docs/spec/slice.md`
- `std.tensor.Tensor<T>`（固定 ABI 描述符）：`cai/docs/spec/tensor.md`

编译器/标准库可依赖的保证（冻结）：
- `struct` 默认 `repr(C)`；
- `enum` 为 tagged union（tag + payload union）；
- 多返回 ABI 映射为返回一个 `repr(C)` struct；
- `Tensor<T>` 的描述符字段顺序/位宽/对齐固定，允许跨库按值传递描述符实现零拷贝。

---

## 6. 链接、资源与启动性能

与产物和资源相关的可依赖语义：
- AOT 产物：`cai/docs/spec/aot.md`
- 链接：`cai/docs/spec/linking.md`
- 资源嵌入：`cai/docs/spec/embed.md`
- 模块初始化顺序：`cai/docs/spec/import.md`

编译器/工具链可依赖的保证（冻结）：
- 静态链接默认优先；
- `embed` 资源包含进产物，运行时访问不依赖外部文件 I/O；
- 模块初始化顺序确定（深度优先、从左到右）。

这些保证允许工具链做：
- 冷启动路径优化（减少动态加载与 I/O）；
- 更稳定的产物布局与可复现构建。

---

## 7. 明确不承诺的内容（避免过度优化假设）
本规范明确不承诺以下内容，以避免编译器做出不正确的全局假设：
- 不承诺跨模块的全程序别名分析一定成立（除非工具链显式开启 LTO 并可证明）。
- 不承诺“所有失败路径都是冷路径”；冷/热仅可作为启发式，不得影响语义。
- 不承诺特定 CPU 指令集、向量宽度或特定后端 IR 的存在；后端选择不影响本规范语义。
