# 链接（Linking）规范

Status: Frozen

本文件冻结 CAI 的链接策略：静态/动态选择、链接顺序与符号冲突规则。

---

## 1. 静态优先
默认策略冻结为“静态优先”：
- 当同一依赖同时存在静态库与动态库可用形式时，默认选择静态库参与链接。
- 选择动态库必须由构建配置显式指定（配置文件格式不在本文件冻结范围内）。

---

## 2. 链接输入顺序
链接器输入（对象文件/静态库/动态库）的顺序必须由工具链确定并保持稳定，可被用户通过构建配置影响（例如显式列出依赖顺序）。

符号解析顺序冻结为：
- **从左到右**扫描链接输入；
- 未解析符号使用“首位匹配”（first match）规则选择第一个可用定义。

---

## 3. 符号冲突

### 3.1 非弱符号（strong）
重复定义非弱符号必须中止并报错：
- 若在同一次链接中出现同名 strong 符号的多个定义，链接失败（错误必须指明冲突来源）。

### 3.2 弱符号（weak）
CAI 工具链必须支持把导出符号标记为 weak（用于提供可覆盖的默认实现）。

标记方式冻结为 `@attribute`：
- `@weak`：只能用于带 `@export` 的顶层 `fn`；将其导出符号标记为 weak。

冲突规则冻结为：
- strong 与 weak 同名时：strong 胜出；
- weak 与 weak 同名时：使用“首位匹配”选择第一个定义。

---

## 4. 与产物类型的关系
- `exe`：必须完成最终链接，产出可执行文件。
- `staticlib`：产出静态库供宿主链接；符号冲突规则在宿主最终链接阶段生效。
- `dylib`：产出动态库；导出符号集合由 `@export` 决定（见 `cai/docs/spec/aot.md`）。
