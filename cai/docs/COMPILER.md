# CAI 编译器管线（Compiler Pipeline）

Status: Frozen

本文件冻结 CAI 编译器在 IR 分层上的总体结构与边界：默认管线为 `CAI -> MIR -> LLVM IR`；仅 `tensor` 相关计算需要 `MLIR` 层。

本文件不要求特定实现细节（数据结构/Pass 名称/后端工具版本），但冻结“哪些语义必须在某一层保留”与“哪些域允许引入 MLIR”。

---

## 1. 总体分层（必须支持）

### 1.1 前端
- `cai/parser.g4` 负责语法解析，产出 AST。
- 语义分析/类型检查后进入 MIR 生成阶段（MIR 必须可由语义正确的 AST 生成）。

### 1.2 默认后端（必须支持）
默认 AOT 编译管线冻结为：
- CAI AST/语义 -> **MIR** -> **LLVM IR** -> 目标平台对象文件/链接产物

约束：
- 除 tensor 相关 lowering 外，编译器不得依赖 MLIR 才能完成编译；即“无 MLIR”仍必须能编译完整语言与标准库（不含可选域）。

---

## 2. MIR（中间表示）职责（冻结）

MIR 是 CAI 的主 IR，必须承载以下信息：
- **所有权与借用**：保留足以进行借用冲突检查与逃逸限制的结构信息（见 `cai/docs/spec/ref.md`、`cai/docs/spec/slice.md`、`cai/docs/spec/ownership.md`）。
- **错误模型**：保留多返回与 `int` 错误码语义以及 guard `? {}` 的控制流形态（见 `cai/docs/spec/error.md`、`cai/docs/spec/expressions.md`）。
- **可预测求值顺序**：不得在 MIR 优化阶段改变语言冻结的求值顺序与短路行为（见 `cai/docs/spec/expressions.md`）。
- **ABI/布局边界**：跨 FFI/导出边界处必须遵守 `cai/docs/spec/abi.md` 与 `cai/docs/spec/ffi.md` 的约束（例如多返回映射规则）。

允许的优化类型（不绑定具体实现）：
- 常量折叠、死代码消除、公共子表达式消除、边界检查消除（在可证明安全前提下）、内联、循环优化等。

---

## 3. MLIR 层的使用边界（冻结）

### 3.1 必须使用 MLIR 的域：`tensor`
对 `std.tensor` 与张量/算子计算（包括 reshape/transpose/strides 推导、融合、向量化、后端选择等），编译器允许并推荐引入 MLIR：
- CAI MIR（保留高层算子语义）-> MLIR（结构化 IR）-> LLVM IR（或其他后端）

该选择的目的：
- 在“形状/步长/别名”可表达且可验证的 IR 上做优化与 lowering；
- 把 tensor 相关优化的复杂性局部化，不影响语言其他部分的编译复杂度。

### 3.2 可选使用 MLIR 的域（只有在明确纳入标准库/工具链目标时才启用）
除 tensor 外，只有当工具链将其明确作为“可结构化优化域”时，才允许引入 MLIR：

1) **SIMD/向量化友好的字节/数值流水线**
   - 典型：JSON/CSV/压缩/加密/正则/UTF-8 校验等；
   - 目标：自动向量化 + 布局/边界证明，使高层实现接近手写 SIMD 的性能。

2) **GPU/异构后端（非 tensor 但数据并行）**
   - 典型：图像/信号处理、物理仿真、批量几何计算等；
   - 目标：把可移植加速做成语言/标准库能力，而不是仅依赖 FFI。

3) **可验证的内存视图变换**
   - 典型：`Slice`/`Tensor` 的视图变换、bounds 证明、别名分析辅助；
   - 目标：让“消除边界检查/避免不必要拷贝/更激进向量化”可在静态证明下成立。

启用条件（冻结）：
- 该域必须有明确的高层语义规范（SPEC）与可观察行为边界；
- 该域必须有稳定的 lowering 合同（例如固定 ABI 描述符或明确的内存视图语义）。

### 3.3 明确不建议引入 MLIR 的域
以下部分优先保持 `MIR -> LLVM IR`：
- 普通控制流
- 对象/容器与一般业务逻辑
- 错误码/guard
- 模块系统与导入
- FFI/ABI
- 大部分 `std.fs/std.process/std.thread` 等系统编程逻辑

理由（规范性说明）：
- 这些域主要受益于传统 SSA/CFG 优化与后端成熟优化；
- 引入 MLIR 只会增加编译器复杂度与维护成本，而收益不稳定。
